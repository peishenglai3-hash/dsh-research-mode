## 1. 唯一主线

> **T1′ · 阅读证据在锚点级闭合——解析器留在外部，证据层自己证明自己。**

这不是原计划里那个"让产品内的 PDF 转换跑通"。P-07 的实测把那个版本否掉了：

- MCP 转换**能成功**，但耗时 **115 s 与 317 s**（同一文件、同一进程参数），`toolCallTimeoutMs` 必须 600000；
- MCP 只给 `anchor:#/texts/N`，**不给页号**；页号只存在于 CLI 结构化输出。

所以真正该被工程化的不是"解析"，而是**"凭什么说这条笔记读过那篇文献"**。答案是一个可检验的三角形：

```
源文档 sha256  ── 锚点 + 逐字原文 ──  研究笔记（不可变 Artifact）──  读回时重算字节
```

`tools/w03/verify-reading-loop.mjs` 把这三条变成命令，并且**故意不依赖解析器**（用录制好的 parse fixture），所以它能在 CI 里跑。

**配套（强制）：** T2「证据诚实可见」——CI、`payloadVerified`、Hub 派生一致、安装路径如实。

**我牺牲了什么（必须写下来）：**

1. **页级引用本轮没有实现。** 用户能在笔记里得到"锚点 + 逐字原文 + 源哈希"，但得不到"第 7 页"。要么接受锚点级，要么走 CLI 预处理（有页号，但要 shell 且首次联网）。
2. **`available` 的字段语义没改。** 只在输出层加了 `payloadVerified`、在 UI 上标注"有记录 ≠ 已验证"。字段级 `mode` 要 ADR。
3. **逐工具授权没有动。** 它不过 R；继续记 `OPEN-EXEC-AUTHZ`。
4. **没有开 GUI。** 产品内一次完整"读 PDF → 记笔记"的会话轨迹仍是 `NOT VERIFIED`。
