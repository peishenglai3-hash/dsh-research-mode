# W04 · 裁决与下一阶段规划

**输入：** 8 份愿景批判（`docs/w04/vision/`）+ 生态调研（`docs/w04/landscape.md`）+ 现状核验（`W04-NORMALIZE.md`）
**判据（先写死）：** ①**愿景契合**（保护人对知识的追求 / 普惠 / 开放 / 自由探索 / 共创）②**可维护**（不增第二真源、有自动检查）③**可实现**（C0–C1 能落地，C2 需单独立项）

---

## 1. 收敛：八份独立报告指向同一个缺口

| 报告 | 它认为缺的那件东西 |
|---|---|
| v1 政治经济学 | 归档不带权利账与生产账 → `.science` 只"可拷贝"不"可交接" |
| v2 认识论 | 七面只有"有/无"，没有**断言**；记录的是生产过程，不是知识可辩护性 |
| v3 认知科学 | 没有测量"理解是否发生"的机制 |
| v4 HCI | `/7` 把「记录 / 可核对 / 已判定」压成一个数 |
| v5 架构 | 组合无内容身份；复核史不是链 |
| v6 科学社会学 | 只有产物账，没有**承认账**（谁接受/退回/异议） |
| v7 教育公平 | "普惠"是存储命题，不是可及性命题 |
| v8 AI 边界 | 没有测"读得对不对"的东西 |

**五份（v1/v2/v4/v5/v6）收敛到同一件事**：

> **把"证据"从过程记录升级为可核对的断言账本；把"共享"从可拷贝升级为可交接。**

这就是 W04 的主线。另外两份（v3/v8）指向"测量"，v7 指向"可及性"——它们不是主线，是主线的**验收条件**。

## 3. 主线（唯一）

> **W04 主线：断言账本（claim ledger）——让每条论断都能指回"哪一处原文、什么强度、谁担保"，并让这份账可交接。**

**为什么是它**：五份报告独立收敛；它是 C1（加字段/加文件，不改既有语义）；它把"证据"从"文件存在"变成"断言可核对"；它同时服务 v6 的信用与 v7 的可及性（断言账是纯文本，可被任何人读，不需要额外算力）。

**为什么不是"签名链"**：C2，需要 ADR 与迁移；而且没有断言账时，签名链只能证明"文件没被改"，仍不能证明"论断有依据"。

**为什么不是"离线降级"**：C2，依赖打包与模型；先有断言账，才谈得上离线读什么。

## 4. 分阶段路线

| 阶段 | 内容 | 等级 | 出口 |
|---|---|---|---|
| **E1** | **断言账本**：一种新的 artifact kind `claim-ledger`（纯 JSON，随项目走），字段 `claims[]{text, anchor, quote, strength, scope, falsifier?}`；`tools/w04/verify-claims.mjs`：每条 `quote` 必须逐字存在于解析 fixture 的对应锚点，且 `text` 非空 | C1 | 改前失败/改后通过；负例（编造引文）必红 |
| **E2** | **`accounts` 附键**：`getProvenance` 返回 `accounts{rights, producedBy, contributors, claimLedger}`；缺失一律 `unavailable`，绝不默认 `free`；`producedBy.mode:'reported'` | C1 | 测试：旧 artifact 显示 `unavailable`；新 artifact 带 `claimLedger` 指针 |
| **E3** | **界面去评分**：Hub 证据卡从 `N/7` 改成三层（记录 / 可核对 / 已判定）；`已判定` 仅在 `signatureValid===true` 且 `reviewer!==author` 时出现 | C1 | 测试：三种状态各一例；`/7` 字样消失 |
| **E4** | **承认账**：`contributors[]` + `guarantor`；「已复核」只在 `other + verified` 时可用（文案规则进检查器） | C1 | 检查器断言：自审记录不得出现"已复核" |
| **E5** | **测量**：10 条金标断言（合成夹具）+ 一次故障注入（删一个 quote → 必须红） | C1 | 两条命令，CI 里跑 |
| **E6** | **可及性最低两条**：a11y 机检（role/aria-live/tab 语义）+ 发布门槛文档（设备/离线/中文/可及性四道） | C0 | CI 步骤 + 文档 |

**明确不做（本轮）**：签名链（C2）、集合锚（C2）、OIDC（出局）、离线降级（C2）、中文检索路由（C2）、`research.manifest`（C1 但非本主线）、任何"自动生成综述/论文"的能力。

## 5. 验收标准

1. `verify-claims.mjs` 在 CI 里跑：编造引文必红（负例控制）。
2. `getProvenance` 对旧 artifact 报 `accounts.unavailable`，对新 artifact 报 `claimLedger` 指针；**没有任何路径默认 `free`**。
3. Hub 不再出现 `/7`；三层状态各有一条测试。
4. 「已复核」在自审记录上不出现（检查器断言）。
5. `66+N` 全绿；CI 绿。
6. 文档：`docs/w04/` 八份愿景 + 生态 + 归一 + 本规划 + QA。
7. 推送：GitHub main 与本地 tree 一致；本地 `desktop` 在下次重启后加载新版本（npm 发布需 2FA，拿不到则记 `PARTIAL`）。

## 6. 对愿景的两条修正（来自 v6/v7，我接受）

1. **"知识普惠"改为一个可测命题**：普惠 = **降低"使自己的工作可被检验"的成本**，不是"提供更多功能"。发布门槛按 v7 的四道（设备/离线/中文/可及性）逐条写，做得到几条写几条。
2. **"共创"改为一个可声明命题**：共创 = **分工可声明、可争议**；不承诺"人人都能协作"，只承诺"协作了能被看见、能被质疑"。
