# W04 · 愿景 v2 · 认识论维度：AI 参与之后，"证据"还剩下什么

**基线**：`dsh-research-mode-public` @ `20a2df7`（`w03-reading`）。行号取自 `git show HEAD:<path>` 快照——本轮我读取期间工作树被并发删除 61 个 `plugins/` 文件（`git status` 全为 ` D`），我只读、未参与，故一律以 HEAD 快照为准。
**约束**：只读、禁网；未运行任何研究工具（运行会写 `.research`）。唯一写入为本文件。
**边界**：只评认识论（什么算证据、谁负责、谁解释），不重复 W03 的工程缺陷；与 W03 重叠处只解释"为何补不上"。
**理论引用**：离线未核对版本与页码。Foucault（检查/examen）、Boltanski（评判装置/正当化）、Bourdieu（合法性/区隔）只作概念指向，不作引文；其原文措辞一律 NOT VERIFIED。

**一句话结论**：这套系统记录的是**生产过程的可复核性**，不是**知识的可辩护性**；七面越齐全，这个差别越容易被误读。v2 缺的不是字段，是**断言**。

---

## 0. 五个直接回答

1. **AI 参与的"证据"现在究竟是什么**：只有两样——*痕迹*（有字节、有哈希、有几段 caller 自述的字符串）与*可复核性*（读者能重算哈希）。缺第三样：*支持关系*（哪一句话凭什么成立）。痕迹是因果史，支持是规范性关系；系统拿前者当后者用。
2. **可证伪性**：系统里没有一个"真值可及"的对象。artifact 是 blob，review 是挂在 blob 上的决定。可证伪性缺的不是字段，是一个**命题**——没有命题，就没有可为假的东西。
3. **来源责任**：签名保证"这一轮没被改过"，不保证"有人说过这句话并为它负责"。默认配置（`RESEARCH_REVIEW_AUTH=off`）下，任意代理可以给自己签一个 `accept`；`authority` 是自述。结果是：**没有人撒谎，也没有人断言**。
4. **解释权归谁**：三层——schema 作者（决定什么形状算证据）、记录者（决定字符串写什么）、汇总的 LLM（决定怎么叙述）。被追责的人（作者）是记录里**最少出现**的那一方；不被追责的模型是**因果份额最大**的那一方。
5. **"共创"会不会造出无法归责的混合文本**：会。更准确的描述是"有完整性、无断言"。归因（谁造成了这句话）与归责（谁为它负责）被同一个空格吞掉——系统里没有作者字段，而这恰恰是唯一需要它的地方。

## 1. 破坏（5 条）

### EPI-01 七面记录的是"生产过程"，不是"支持关系"——这是范畴错误，不是覆盖不足

**论断**：七面（code / execution / environment / messages / reproducibility / review / literature）全部是因果史字段，回答"这些字节怎么来的"。读者要问的是规范性问题："我凭什么可以相信这句话"。两者不可互推：一段文字可以出身完美而胡说，也可以出身可疑而正确。系统没有任何字段是"内容为真"的函数，所以"七面齐全"与"主张为真"在结构上无关。

**证据**
- `store.js:195-213`：artifact 字段全集（id / title / kind / projectId / createdAt / bytes / checksum / source / provenance）里没有 author、没有 claim、没有 target proposition。
- `store.js:204-212`：七面全部由 `face()` 包装，值是 caller 给的字符串或派生值；`reproducibility` = `{checksum, bytes, source}`，前两项由同一 buffer 派生（W03 ARCHC-02 已证其不可为假），第三项只是 `basename`。
- `store.js:239-323`：`getProvenance` 返回 `faces / payloadVerified / reviewSource / reviewSnapshot`；逐字段检查，没有一个是内容正确性的函数。
- 反向构造：把 `2+2=5` 与 `2+2=4` 以相同 title/kind/faces 分别记录，两面结构完全同形，只有 id 不同。这不是 bug，是数据模型的性质。

**为什么这是认识论问题**：W03 已指出 "N/7 会被当成可信度"（`W03-GAP-MATRIX.md:21`）。本条说明**为什么补不上**：七面只有"有/没有"，没有"强/弱"，因此聚合不是缺失的 UI，而是**没有可聚合的量**。要补，必须先造强度，而强度的单位只能由**命题类型**给出（见 T2）。还有一层：论文是断言的合取，而 review 是对 blob 的单一决定——合取式判断在文档粒度上先天失效：一处编造引文与一处措辞存疑，得到同一个 verdict。

**severity**：high
**falsifier**：构造性证明——固定 title/kind/project/其余六面，只把 `content` 的真值反转，找出 `research_provenance_get` 返回值中**任何一个**随之改变的字段。找到即推翻本条。

### EPI-02 没有作者字段：AI 与人的贡献在记录里不可区分，"来源责任"只剩自述

**论断**：artifact 无 author/contributor 字段；`messages` 是自由字符串（`index.js:88`、`store.js:208`），而 research-host 不读 DSH 会话库（`index.js:3` 自述 "No DSH imports"；全仓无会话内容读取），所以这个"锚"解析不回任何真实消息。于是"AI 参与了哪一部分"在数据模型里没有位置——它只能以叙述形式出现在字符串里，而字符串的作者身份同样不可知。更尖锐地说：**七面记录的是 AI 协作中最不像 AI 的那部分**（计算可重放），而最像 AI 的那部分（怎么读、怎么摘、为什么选这条来源）没有面。

**证据**
- `index.js:80-92`：`research_artifact_record` 参数表 = projectId / title / kind / source / content / code / log / environment / messages / review / literature。无 author、无 model、无 contributors。
- `store.js:208`：`messages: face(input.messages, …)`——值即 caller 传入的任意字符串，无校验、无外键、无解析。
- `store.js:377`：`reviewer: String(input.identity?.sub ?? input.reviewer ?? '')`——默认空串仍被接受（`recordReview` 对 reviewer 无 required 校验，`store.js:342-402`）。
- 全仓 grep `author`：只命中 connector 元数据与 review 的 `authority` 枚举，没有"artifact 的作者"这一概念。

**为什么重要（制度后果）**：学术不端调查问的第一个问题是"这条编造引文是谁写的"。在此记录里：artifact 不署名，`literature` 是字符串，`review` 是决定，`messages` 是自述——**唯一能回答该问题的材料，恰恰是系统不记录的那一类**。这不是隐私保护，是证据链在最需要它的地方为空。

**severity**：high
**falsifier**：同项目记录两个 artifact，一个完全由 AI 会话产出、一个全手写，其余参数（含 faces）相同；dump 两个 sidecar，若存在任一字段能区分二者（title/时间戳/id 除外），本条被推翻。另：若任一代码路径把 `messages` 解析回会话存储，亦推翻。

### EPI-03 "复核"不是反驳通道：默认无身份、角色自述、且没有作者可供冲突检查

**论断**：review 是**决定**（accept/revise/reject）+ 自由文本 notes，绑定在 artifact 上；它不是对某个命题的反驳。系统没有"某主张被某来源否定"的对象，也没有"谁可以向谁提出异议、异议落在哪里"的位置。叠加三件事——默认认证关闭、角色自述、无作者字段——最小配置下的复核记录可以是：任意代理给自己签一个 `accept`，签名校验通过，记录显示"已复核"。

**证据**
- `auth.js:34`：`RESEARCH_REVIEW_AUTH ?? 'off'`；`index.js:143-146` 的 token 校验整段位于 `mode !== 'off'` 分支内，故 off 模式下 `accept` 不需要任何 token。
- `store.js:351-352`：`authority` 由 input 自述，只做枚举校验（`store.js:325-327`）。
- `store.js:377`：reviewer 可为 `''`；`notes` 默认 `''`——最小可接受记录可以除 decision 外全空。
- `store.js:477-481`：`verifyReview` 自述 limitations（不是 Merkle log、旧轮可删不可检）；W03 已提，此处只用来说明"历史不完整"与"身份不可证"叠加后的结果。
- 全文无 author 概念 → "作者不能当审稿人"这条学术常识无法被编码。

**为什么重要**：可证伪性要求"有人提出一个可错的断言，并被反驳"。这里断言没有主体、反驳没有对象、决定没有身份。三者叠加，复核记录能证明的只有**这个文件没被改**。签名是封条，不是责任书。

**severity**：high
**falsifier**：默认环境下（不设 `RESEARCH_REVIEW_AUTH`）对任一 artifact 记录 `decision:'accept'`、`authority:'auditor'`、不传 reviewer/token，再 `research_review_verify`：若返回 `valid:true` 且记录无身份，本条成立；若任一环节要求身份、或检查 reviewer 与 author 冲突，本条被推翻。

### EPI-04 解释权由 schema 先行分配：七面的形状是计算实验室的形状，质性证据只能以自由文本入场

**论断**："field-agnostic" 是关于**词表**的声明，不是关于**形式**的声明。七面中 code/execution/environment/reproducibility 是计算产出的面，messages 是会话的面，literature 是"文献定位符"的自由文本。研究者手里的证据对象——访谈录音、田野笔记、编码手册、双编码者分歧、受访者撤回同意、观察者位置——**没有一个有语义正确的面**，只能塞进 literature（错类）或 messages（错类）。谁决定什么算证据？不是用户，是数据模型的作者。

**证据**
- `store.js:27-30`：`FACE_KEYS` 七项；`store.js:204-212` 逐面 `face()`。
- `docs/EVIDENCE-MODEL.md:29-39`：literature = "citation locators (free text)"，`locators were entered ≠ the citation is correct`。
- `skills/evidence-audit/SKILL.md:12-21`：纪律已存在（claim/source/evidence level/gap 表、"未读全文"标注），但**没有对应的记录结构**——agent 交出的审计表落盘后只是一个 blob，逐条结构在记录时即被抹平。纪律在文本里，记录里是空的。
- 仓库不存在接受"断言"的参数：plugins 内 grep `claim` 只命中注释与测试文本。

**为什么重要（与"知识普惠"的冲突）**：一个只能以计算痕迹入场、质性证据必须降级为散文的装置，对已有 CLI/git 习惯的研究者是低税，对田野研究者是高税。若用它衡量"谁的知识更可核验"，就是把**方法资源差异**转写成**认识论等级**——这正是作者关心的数字不平等，只不过发生在知识论层面（评价装置 → 可识别性 → 合法性，Boltanski/Bourdieu 的问题域）。这是本轮最重的一条：它不否定工具的用处，而是否定"普惠"可以靠扩张工具达成。

**severity**：high
**falsifier**：对 (a) 访谈录音 (b) 田野笔记 (c) 双编码一致性 (d) 受访者撤回同意，逐一指认一个**语义正确**的面并给出记录它的工具参数路径。四者皆有 → 推翻；任一只能靠自由文本 → 成立（我预测四个都只能靠自由文本）。

### EPI-05 七面齐全可能"洗白"可信度：审计痕迹替代判断（设计推断，未做实验）

**论断**：当读者看到"7 面齐全 / `payloadVerified: true` / `valid: true`"，得到的是一个**仪式性**信号，其认知内容很窄（没被改过、有几条自述、有一个决定）。可预期的效果是：痕迹提高了对**内容为真**的主观置信，却没有提高错误检出率。若成立，则"更诚实的 UI"在净效果上可能是**可信度洗白装置**——与意图相反，且与 EPI-01 同源。

**证据**
- 现状：`README.md:95-112` 与 `EVIDENCE-MODEL.md:33-40` 用大量篇幅纠正误读，说明团队已预见此风险。
- W03 已观察：复核卡不渲染 `auth.verified`、签名与自述同色同行（`W03-GAP-MATRIX.md:65`）、`payloadVerified` 无 UI 消费（`:66`）——仪式与事实在界面上尚未分层。
- NOT VERIFIED：读者行为未测；本条的证据是设计特征，不是实测。

**为什么重要**：认识论上这不是"要不要展示"，而是**展示即断言**：把痕迹放在主张旁边，就是在暗示痕迹支持主张。装置没有中立性，只有被设计过的倾向。

**severity**：medium（后果大，但未验证）
**falsifier**：预注册 A/B——同一段含一处编造引文的文字，A 组附 provenance 卡、B 组不附，测 (i) 置信评分 (ii) 是否指出该引文有问题。若 A 组置信不升且检出率不降 → 本条削弱；若 A 组置信显著升而检出率不变 → 成立（洗白）。

## 2. 理论构型（5 条原则）

### T1 双账本：因果账与支持账分账，禁止共用一个分数
- **原则**：因果账回答"它怎么来的"（可缺、可粗、可后补）；支持账回答"哪一句话凭什么成立"（必须逐命题、可定位、可反驳）。二者可独立失败，故不得共用字段或分数。
- **与政治经济学维度的冲突**：支持账一旦可审计，就变成**可信度资本**——可机器核验的证据类型获得溢价，不能的贬值。分账只是第一步；不配套"低技术成本证据"的合法入口，分账会加速不平等。
- **与架构维度的冲突**：支持账是细粒度、多对多、可修订的，与"不可变 blob + 单文件可 grep"的极简主义直接冲突。出路不是新建 artifact 类型，而是**锚**（claim → blob 内的 span / 精确引文），以追加日志存在于 blob 之外（见 P2）。

### T2 证据等级是"类型相对偏序"，不是全局阶梯；任何全局分（N/7、统一 C 级）都是伪度量
- **原则**：等级只在"命题类型 × 推断层级"内部有序。访谈引文不能支持总体分布；回归系数不能支持意义解释；预注册不能支持机制。故等级必须携带 scope（能支持什么、不能支持什么），而不是一个标量。
- **证据审计 skill 已有推断层级却拒绝给刻度**（`skills/evidence-audit/SKILL.md:16` 只列 observation/association/mechanism/causal）——缺刻度不是疏漏。一旦有全局刻度，它就会被比较、排名、当成资源门槛。
- **与政治经济学维度的冲突**：全局分一旦存在，就会被制度采纳（评审、考核、期刊），重演"方法拜物教"：有资源做高等级证据的人定义什么叫证据。
- **与产品维度的冲突**：一个"证据分"极易做、极易传播、极易被当成质量。本条建议**明确拒绝**并在 UI 上拒绝聚合——这会降低可炫耀性，与增长冲突。

### T3 归因 ≠ 归责：因果份额与可问责的断言必须分开记
- **原则**：模型对文本有**因果份额**（生成候选句、塑造主张空间），但没有**断言地位**（不能被质询、不能被制裁、不能作证）。把两者压成一个"AI 贡献比例"，是用因果量做归责的活。归责需要三要素：可识别主体、可归属行为、可回应的通道（rebuttal channel）。
- **推论**：对混合文本，"谁负责"不能由记录推出，只能由**程序**产生（谁签字、谁被授权、异议落到哪里）。工程目标应是"可申诉"，不是"可证明"。
- **与开源/共享伦理的冲突**：个体归责与集体署名、双盲评审、课题组署名传统冲突；"课题组/导师一作"无法映射到 sub 级身份。这条只能在制度层（谁代表课题组签字）解决，不能靠字段。
- **与架构/安全的冲突**：无密钥哈希是正确选择（本地优先、无 CA），但它把身份永久排除在密码学之外。不要把归责期待放在签名上；签名只承担"记录未被改动"。

### T4 解释权必须可争夺：分歧要被看见，不能被"最后一轮"压缩
- **原则**：一个 artifact 允许两个不相容的解释并存且都可被读到；review 的价值在 disagreement，不在 consensus。`history[]` 是追加的（好），但顶层镜像成单一 verdict（`store.js:385-399`），任何读顶层字段的界面只看到"结论"。W03 已指出 verdict 双源（ALG-03）；本条指出更严重的：**结构性抹除分歧**。
- **与产品/UX 的冲突**：一个"当前结论"最好卖，并存解释最难展示。这是真实取舍，不能假装兼得。
- **与可计算性的冲突**：并存解释不可聚合、不可排序，进不了 dashboard；与"研究仪表盘"的产品直觉冲突。

### T5 未知必须带闭合条件：每个 unavailable 要说清"补上它需要谁做什么"
- **原则**：现状 `unavailable(reason)` 给的是**缺席的原因**（`store.js:205-211`，如 "producer code was not recorded"），不是**补上的路径**。读者（权力更小的一方：学生、外部读者、审稿人）拿到 unknown 后唯一能做的是忽略它。unknown 作为一等状态，只有在它同时是**一等待办**时才成立。
- **与普惠的冲突**：把"未核验"永久标记，会把资源劣势固化为认识论污名。故闭合条件必须区分"可补 / 已永久丢失"（如访谈录音已销毁），否则诚实的装置会变成纹章学。
- **与叙事的冲突**：这会把"诚实"从免责条款变成工作量清单——honesty-as-work 不好卖，但它是唯一不退化为免责的诚实。

## 3. 实践方案（4 个，按依赖排序）

**C 级标度**（我从 W03 用法归纳的操作化，非仓库正式定义，NOT VERIFIED）：C0 ≤0.5 人日且无新持久化；C1 0.5–1.5 人日且只新增只读/追加文件；C2 2–5 人日且触及工具契约或身份；C3 需改协议或人类裁决。

### P1 未知的闭合条件（C0，约 2 小时）
- **机制**：`unavailable(reason)` → `unavailable(reason, closure:{actor, action, cost, permanent?, expiresAt?})`；skill 侧规定每条 unavailable 必须写补齐路径或标 `permanent`。消费点选已有的 `research_replay_plan` 的 gaps 数组（`plan.js:58-64`），不新建 UI。
- **最小实验**：对 7 面全空的 artifact 逐面写 closure，请一人判断"是否具体到可执行"。判决：≥70% 可被独立执行，否则措辞装饰化，应删掉该机制而不是继续加字段。
- **falsifier**：若 closure 在工具返回值与 replay gaps 里都没有消费者（重演 `payloadVerified` 的命运，`W03-GAP-MATRIX.md:66`），则机制是装饰——所以必须与一个消费点同批交付。
- **对应**：T5。

### P2 论断锚点账：claim–span–source–strength–scope（C1，约 1 人日）
- **机制**：追加文件 `.research/projects/<id>/claims/<artifactId>.jsonl`，每行 `{claimId, artifactId, span:{quote,start?,end?}, source:{locator, kind}, strength:{inference, scope, excludes}, wouldChange?, recordedBy, createdAt}`。**关键性质**：quote 是某个已记录 artifact 的精确子串，因此可脚本自检（找得到/找不到）——支持关系第一次**可为假**，与 literature 自由文本相反。
- **二次锚定（针对"无法证明解析器正确"）**：把 Docling 的抽取结果本身记录成 artifact，断言锚到该抽取文本的 span，而不是锚到 PDF 字节。错误于是变成"某一次解析的错误"，可定位、可复现、可替换，而不是"PDF 说了什么"这种不可判定命题。**这是把不可证转成可归因的唯一诚实路径**，也绕开了 PDF 二进制不可子串匹配的问题。
- **最小实验**：取一篇已完成论文的一节，标 10 条断言；第二人独立核 3 条。测 (i) quote 自检通过率（机械应为 100%）、(ii) 每条耗时、(iii) 两人对 strength/scope 的分歧率。判决：每条 >10 分钟或分歧率 >40% → 降级为"只标关键断言，每篇 ≤10 条"。
- **falsifier**：若抽取文本 artifact 本身不可稳定复现（同一 PDF 两次解析字节不同），span 自检在跨机器上失效，P2 退化为自由文本。**这一点必须先测**（NOT VERIFIED）。
- **对应**：T1/T2；为 P3 提供机器可验的下限。

### P3 核验清单替代"AI 贡献比例"（C1，约半天）
- **机制**：贡献记录两栏分开。**因果栏**：模型/路由、参与了哪些节（不存 token 级）。**核验栏**：人实际检查了什么（数字 / 引文原文 / 论证链 / 数据 / 未检查），逐项，可指向 P2 的 claimId。落点 `contrib/<artifactId>.jsonl`（与 claims 同形思想）。
- **为何反直觉**：读者信任受"AI 比例"影响（流畅性启发式），但**保证强度取决于核验，不取决于比例**：90% AI 全核 > 10% AI 未核。把比例做成审计字段会奖励表演（少报/不报），并把归责问题伪造成百分比问题（T3）。
- **最小实验**：5 名读者，两版同一段（各含一处编造引文）："AI 起草 90%（已核引文）" vs "10%（未核）"。测置信与检出。判据：若检出只随比例变、不随核验变，说明读者在用比例当质量信号 → 更该删比例、留核验。
- **falsifier**：若核验栏在实践中总被填成"已核"而无从核查，机制退化为 EPI-02 的自述问题——故 P3 依赖 P2 的 quote 自检来兜底。
- **对应**：T3。

### P4 审稿视角分离：内部一致性 vs 来源一致性（C2，约 2–3 人日）
- **机制**：review 增加两个并列子判断 `coherence`（文本内部是否支持其结论）与 `sourceAlignment`（引文/数据是否与其来源一致），各自 decision；并加规则：同一 subject 不能在同一 artifact 上同时担任 author 与 auditor（依赖 P3 的作者/贡献记录）。
- **为何**：AI 辅助文本的典型失败不是内部矛盾，是**局部连贯 + 来源漂移**（编造引文、错页、把摘要当全文）。合成一个 verdict 会让后者被前者的良好表现掩盖；分离后，分歧本身成为可读证据（T4）。
- **最小实验**：同一 artifact，两名 auditor，分离两轴；测两轴分歧率。预测 sourceAlignment 分歧 >> coherence 分歧；若相反，说明分离是形式主义（或该 artifact 的失败是论证型而非来源型）。
- **falsifier**：若两轴判断在同一 artifact 上一致率 >90%，分离无必要。
- **对应**：T4/T3。

## 4. 接口与"不做"清单

| 关系 | 判断 |
|---|---|
| EPI-01 → T1/T2 → P2 | 中心缺口：支持关系必须成为可记录对象，否则"证据优先"只能是"过程优先" |
| EPI-02 → T3 → P3 | 作者/因果份额缺失，任何"共创"叙事都无法归责；先记核验，再谈比例 |
| EPI-03 → T3/T4 → P4 | 复核要成为反驳通道，需要身份与视角分离；密码学不承担身份 |
| EPI-04 → T2/T4 | schema 的形态即解释权分配；普惠要求质性证据有同权入口 |
| EPI-05 → T1/T5 | "更诚实的 UI"可能更危险；先做 A/B 再定界面 |

**本轮就能做（C0）**：P1。
**下轮（C1）**：P2 二次锚定；P3 核验栏（依赖 P2）。
**不做**：① 全局证据分（T2 已论证其为伪度量）；② "AI 贡献比例"作为必填审计字段（T3）；③ Popper 式"证伪条件"作为必填项——它会在探索期杀死研究，用 `wouldChange`（什么会改变我的看法）代替；④ 外部锚（跨机构时间戳/公告）是"整体换键"的唯一出路，但改信任模型，属 C3，须人类裁决。

**给另外两个维度的要求**：向政治经济学维度要"低成本证据与高成本证据同权"的制度设计（否则 7 面=认证=通行证）；向架构维度要"不做子 artifact，只做 anchor"的克制（否则内容寻址与细粒度记录会互相吞掉）。
