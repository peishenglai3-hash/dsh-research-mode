# W04 · 愿景 v4 · HCI / 交互设计维度

**基线：** `dsh-research-mode-public` @ `20a2df7`（`w03-reading`）。行号一律取自 `git show HEAD:<path>` 快照——写作期间工作树被并行删除又恢复（`git status` 一度 61 个 `D`），磁盘文件不可作为行号依据。
**约束：** 只读、禁网、未开 GUI、未运行任何 `research_*`（会写 `.research`）；唯一写入是本文件。
**证据等级：** `OBSERVED`（HEAD 源码直读）/ `INFERRED`（由代码路径推得）/ `NOT VERIFIED`（需实机或用户实验）。
**边界：** 不复述 W03 的 HCI-01…07 诊断；只回答一个维度问题——**这套产品的交互模型应该是什么，以及凭什么知道它更好。**
**与同批愿景的关系：** v1 政治经济学、v2 认识论、v3 认知科学、v5 架构、v6 科学社会学、v7 教育公平、v8 AI 能力边界；§2.6 写明接口与冲突，不替它们裁决。

## 0. 复原场景与五个直接回答

### 0.1 十五分钟，一条证据（由代码路径复原，不是实拍）

22:40，社会学大二。访谈录音 `interview-03.m4a` 在工作区，我想留下"第三条证据"。
打开左栏"科研" → 四张模板卡 + 一句"本页只读并启动会话" → 填项目名 → 复制创建指令 → 切回会话 → 粘贴发送 → 等 Agent 调 `research_project_create` → 回"科研" → 等 30 次静默轮询 → 点"用此项目启动" → 在新会话里描述要记什么 → 等 Agent 调 `research_artifact_record` → 打开右栏 → 看到"6/7 面有记录（available ≠ 已验证）" → 不知道少的是哪一面，也不知道这段录音能不能按"12 分 30 秒"被引用。
十五分钟里，我做的事是**在面板之间搬运提示词**；系统记下了字节，没有记下我为什么停下。

### 0.2 五个直接回答

1. **现在的交互模型是什么？** 一台"启动器 + 检查器"：左栏立项，右栏看 JSON。中间的过程交给聊天。
2. **最贵的缺口是 15 步吗？** 不是。15 步只是症状；真正的缺口是**做判断的那一刻，证据的状态不可读**——不知道时间、来源、层级、主张。
3. **探索性与可发现性冲突吗？** 当前实现把"探索"外包给了文档：界面不给把手，"自由"就退化成"必须先知道工具名"。
4. **15 步的根因是什么？** UI 没有写 `.research` 的通道，只能组提示词与开新会话（`workspace/client.js:472-473` 的 `sessions.create` 是唯一的非剪贴板动作）。这不是 bug，是"Host-only 单一真源"在交互层的投影。
5. **最小可做的三件事？** 证据分层、派生日志、项目状态 + 会话；都不新增真源。

## 1. 破坏（5 条）

### D1 · "不规定流程"被实现成了"不呈现动作"

**主张：** 界面把探索的自由留给了对话，却没有给探索留下任何可发现的把手；"探索"于是退化为"必须先知道工具名"。

**现场（OBSERVED）：** 左栏页的动作几乎只有：5 个"复制指令"按钮、每个项目 1 个"用此项目启动"与 1 个"复制导出指令"、1 个刷新、1 个返回（`workspace/client.js:319, 361, 383-388`；`hub/client.js:85, 214`）。UI 没有任何动作/能力清单；24 个工具名只出现在两段被复制的提示词里（`research_project_create`、`research_science_export`），其余 22 个从不出现。右栏四个 mode 是存储分类（产物/证据链/复核/文献），不是研究动作；能力入口只有一行 `guide`（`hub/client.js:306-313`）。W03 已量化：首条可复核证据 15 步、12 个用户动作、1 次剪贴板往返（`gap-ux.md` UX-01）。

**更深的一层（OBSERVED）：** preset 的人格大意是"开放阅读不需要项目……创建项目只在确实需要耐久记录时；不要强迫每个问题都走项目记录"（`research-preset/cordis.patch.yml`）。而左栏唯一可见的路径是"填名 → 建项目 → 启动项目会话"。**界面教的和 Agent 说的是两套模型**：对话里可以自由探索，界面上必须先立项。用户要么不信界面，要么把探索也塞进项目。

**认知依据：** 再认优于回忆（Nielsen #6）；探索性搜索需要"结果引发下一个问题"（Marchionini），而界面从不显示一个可被接着操作的结果。

**falsifier（E1 首次留证）：** 8 名社科研究生，不给 README/文档，任务"为你的课程论文留下第一条可复核证据"，5 分钟。记首次成功 record 的时间、步数、外部文档打开次数、放弃率。若 ≥6/8 无文档完成且能说出 3 个"下一步可做的事"，D1 被推翻；若 UI 里出现动作清单/能力表（不是提示词里的那两个工具名），"零枚举"被推翻。

### D2 · 长会话没有方向感：库是状态的，界面就没有历史

**主张：** 数据模型只有状态（project / artifact / review），没有事件；于是界面只能回答"有什么"，不能回答"刚做了什么、变了什么、下一步是什么"。

**现场（OBSERVED）：**
- 同字节再记录直接返回 existing，不追加时间（`store.js:186-187`）——"记录"这个动作在库里不可见；
- artifact 有 `createdAt`（`store.js:200`），Hub 不渲染；review 有 `createdAt`（`store.js:338`），卡片不渲染；
- Hub 的 effect 只依赖 `[sessionId, refreshNonce, chosen]`，不轮询、不订阅；刷新前先清空（`hub/client.js:98-107, 167`）；
- 左栏"最近会话"是一句静态说明（`workspace/client.js:388`），不是列表；
- sidecar 无 `sessionId`（`store.js:195-213`），无法回答"这条证据是哪次会话留下的"；
- 页脚恒为 `research-hub · 科研 / Research`（`hub/client.js:297`），不携带项目/时间/会话。

**后果：** 3 小时或 3 天后，恢复现场的唯一路径是翻聊天记录。而聊天记录可能被 compaction 压缩（preset 里 `compaction-basic` 在场），不进 `.science`，也不可引用。

**认知依据：** 情境意识三层（Endsley 1995）：界面停在"感知"，没有"理解"与"预测"；中断恢复依赖目标记忆（Altmann & Trafton 2002）。

**falsifier（E2 中断-恢复）：** 12 人，25 分钟任务，10 分钟中断，回来不给看聊天记录；若中位恢复时间 ≤30 秒且 ≥10/12 一次回到正确步骤，D2 被推翻。辅助：两周日记里"定向动作"（翻聊天/重开文件/问 Agent 我们到哪了）若 <1 次/30 分钟，D2 弱化。

### D3 · 信任信号：一个"存在性比例"被放在了"可信度"的位置

**主张：** `6/7 面有记录` 是七个异质信号的计数，不是置信度；界面上唯一的比例承担了它承担不了的判断。用户把它读成"完成度/已验证"，是界面诱导，不是用户误读。

**现场（OBSERVED）：** 七面 = 4 个调用方自由文本（code/execution/messages/literature）+ 1 个可被调用方覆盖、缺省自动填充的 environment + 1 个写时计算（reproducibility）+ 1 个读时派生或调用方自述（review，看 `reviewSource`）（`store.js:204-212, 250-254`）；每个不可用面的人话 `reason`（`store.js:205-211`）与 `payloadVerified/payloadBytes`（`store.js:299-318`）工具已返回、界面从不渲染；review 的 `decision` 用品牌色（`hub/client.js:267`），而 `auth.verified` 不渲染；checksum 一律截 16 位（`hub/client.js:291`），看起来像校验。W03 已把文案改成"available ≠ 已验证"，但数字仍在（`crit-hci` HCI-01）。

**为什么不能靠"更诚实的文案"解决：** 七面没有共同刻度，聚合本身没有意义（v2 EPI-01 的范畴错误）。一个诚实的 `/7` 仍然是 `/7`。问题不在措辞，在于**把不可相加的东西相加了**。v3 D2 的"三条阅读路径在界面上都叫'读过这篇'"是同一病理的另一处：界面把强度不同的动作压成同一个词。

**认知依据：** 信任校准（Lee & See 2004）；精确性幻觉（16 位哈希、/7 分数）；自动化偏见。

**falsifier（E3 信任校准）：** 2×2，n=40。当前 `/7` vs 分层卡；6 条 claim 分类（"可引用为已复现"/"环境是我的"/"有人类批准过"…）+ 置信度；过度信任率 = 把"有记录"判成"已复现/已验证"的比例。若当前界面过度信任率 ≤10%，D3 被推翻；若分层卡降幅 <15 个百分点，M3 失败。**前置：** 先跑 v2 EPI-05 的"附卡 vs 不附卡"——若附卡只升置信不升检出，任何证据 UI 都不该先上线（v2 的一阶否决权）。

### D4 · 可中断/可恢复：数据是耐久的，意图不是

**主张：** 产品能恢复"文件"，不能恢复"我做到哪、下一步做什么"。研究的大部分时间在飞行中（搜索、读、想、决定不记录），这些不落盘，也没有界面承接。

**现场（OBSERVED）：** UI 没有任何写 `.research` 的通道；唯一会在系统里产生新对象的按钮是 `sessions.create`（`workspace/client.js:472-473`）。复制指令一次性，剪贴板失败只留一句同色提示（`workspace/client.js:235, 326`）；项目页不显示 artifact/review 计数、最后活动、关联会话；没有草稿/暂存/停车；"最近会话"静态（`:388`）；右栏四个空态都是陈述句（`hub/client.js:178-186`），没有一个带动作；preset id 写死 `'research'`（`:473`），只装 `research-cn-social` 时"用此项目启动"可能失败（INFERRED）。**"可恢复"有两层：** 崩溃恢复（文件在，成立）与认知恢复（意图在，不成立）；产品把前者当成了后者。

**认知依据：** 前瞻记忆与目标记忆；恢复延迟随任务嵌套增长；外部化"下一步"是最便宜的干预（v3 的 P3 已给出会话级版本，本维度要项目级）。

**falsifier（E2 同批）：** 中断后能否在 20 秒内说出下一步并回到正确步骤；若 ≥80% 可以，D4 被推翻。另：统计重复记录/重复检索率；若 <10%，机制可能不必要。

### D5 · 多模态缺席：字节能存，意义不可寻址

**主张：** artifact 的单位是"字节 + sha256"，可读的单位是"文本/PDF 锚点"；访谈录音、田野照片、手写笔记、白板机制图只能作为不透明 blob 进入，不能按"第 12 分 30 秒那句话"或"白板左下角那个箭头"被引用。社科经验研究的原初材料因此被排除在可复核循环之外。

**现场（OBSERVED）：** record 只接受 source/content（`store.js:170-178`），`kind` 自由字符串；sidecar 无时间轴/区域/转写字段；阅读链是 PDF→文本锚点（Docling，115–317 秒）；`literature` 面是自由文本（`EVIDENCE-MODEL.md:29-39`）；没有音频/视频/手写/白板工具。v2 EPI-04 已从认识论指出"质性证据只能以自由文本入场"；本条补的是**交互后果**：不是少一个播放器，而是"谁的材料能被算作证据"。

**认知依据：** 编码特定性——回到原始模态/语境更利于核对；输入成本决定捕获率；最贵的证据系统是让人当场放弃记录的系统。

**falsifier（E5 田野小实验）：** 5 名社科学生、每人 2 次访谈；text-only vs audio-anchor stub。测 24 小时内捕获率、复核者定位一句引文的时间、主观费力。若 text-only 捕获率 ≥80% 且定位 <60 秒，D5 被推翻。**注意：** 这条即便成立也是 C3，不在本轮施工。

## 2. 理论构型（5 条原则，逐条标冲突）

**P1 · 可逆性优先于确认性。** 任何写入相邻的动作先可预览、可撤回；不可撤回的（记录、导出、accept）必须有独立的"提交"语法，不能与"草稿"同形。
- 冲突（架构）：artifact 不可变、内容寻址，没有 tombstone（v5 T2：内容身份是唯名论的，派生边才回答"从谁改出来"）；"撤销"只能是"新版本替代/撤回复核"，界面必须显示替代链而不是假装编辑。
- 冲突（认知）：用户对"编辑"的心理模型很强；把"编辑"从词表删掉有教学成本。
- 合题：C1 只能做到"不假装可编辑"；真替代链要 sidecar 加 `supersedes`（C2，无迁移，缺省 null）。

**P2 · 渐进披露以"主张"为单位，不以"文件类型"为单位。** 首屏回答"你在核对什么主张"，只展开相关面；"看全部七面"是逃生门。现有四 tab 是存储分类，不是任务分类。
- 冲突（架构）：七面固定；claim→face 映射必须是内容表，不是新 schema。
- 冲突（认知）：专家要密度；隐藏数据可能家长式；"合意困难"提醒别把核对摩擦全磨平（v3 的摩擦预算）。
- 合题：三层摘要 + 完整 JSON 一键可达；不做 claim 存储（C3；若做，归 v2 P2）。

**P3 · 时间线优先于列表。** 默认视图应是"发生了什么"的时间线，不是"有什么"的列表；未知与缺口显式标注。
- 冲突（架构）：库是状态不是事件；去重隐藏记录动作；无 sessionId；同秒排序未定义；真日志 = 第二真源（禁止）。
- 冲突（认知）：时间线会被读成"完整历史"；必须标注"搜索/阅读/决定不记录没有留下记录"，否则制造更高级的虚假。
- 冲突（v6 后台权）：全记录会取消后台、改变被记录的行为；时间线只做"已落盘的"，不要求补记搜索/阅读/放弃——"未记录"是设计，不是缺口。
- 合题：派生时间线（C1），明确标 `derived`；append-only journal 走 ADR（C3）；不显示"研究时长"等可被 Goodhart 的指标。

**P4 · 场景化入口：从"手头有什么"进入，不从"产出体裁"进入。** 四个模板是"产出体裁"（文献综述/数据分析/图表报告/论文复现），它们假设用户已经有材料且知道体裁；真实起点是"我有录音/我有数据集/我被拒了/我有个半成品论证"。
- 冲突（架构）：preset 与入口写死耦合（`agentPreset:'research'`）；每个场景映射不同工具；入口分支增加维护；UI 不能写，只能组 prompt。
- 冲突（认知）：选择过载；4 个已是上限；需要"以上都不是"。
- 合题：最多 4 个材料入口 + 1 个"我还没有材料"；每个入口生成一段可编辑的 intent brief，不直接建项目（避免空项目）；探索态不出现日志、不落盘（v7 T3 的分层：探索态默认不落盘，交付态才全链）。

**P5 · 信任分层：记录 / 可核对 / 已判定（含有争议）是三种东西，不能相加。** 每一层有自己的来源、时间与失败模式；界面只描述，不评分。
- 冲突（架构）：身份校验默认 off（`auth.js:33-40`）；签名无密钥；无外部锚点 → "已判定"层可能为空，界面必须说"本机未启用身份校验"而不是省略。
- 冲突（认知）：三层提高负荷；用"一行摘要 + 展开"而不是更多常驻信息。
- 冲突（v8/v2）：把面标成 `declared` 会被读成"不可信"、降低采纳（这是 v8 的 warrant 词表在 HCI 上的已知风险）；解法是中性描述与排序，不是红/绿。全局分（N/7、统一 C 级）是伪度量，拒绝。
- 合题：M3。

### 2.6 与 v1 / v2 / v3 / v5 / v6 / v7 / v8 的接口

- **v2 的 EPI-05 是本维度的一阶否决条件：** 先证明"附证据卡"不是洗白，再谈分层；否则 M3 可能只是更精致的仪式。
- **v3 的摩擦预算我接受：** M1/M2/M4 减的是事务性摩擦；M3 增加的是解释性摩擦，但可见、可跳过、留痕。深读窗口与回忆检查点归 v3，不进我的时间线。
- **v5 的单一解析器（T1）与"禁止 catch → []"（T4）直接约束我：** 派生视图不许再写第六份 cwd→root 正则；M1 的会话归属只是 UI 近似，必须标"疑似"，不能用于证据归属；所有空态必须四态（loading / empty / error / partial），否则时间线会重演"读不到 = 没有"。
- **v6 的"已复核"是关系谓词（P2）与后台权（P3）：** M3 只写"自述复核"，不写"已复核"（作者字段不存在，UI 无法判断他审）；时间线只显示已落盘的事，"未记录"是合法状态。导出档案不携带告诫（v6 D-03），HCI 修不了，需要导出字段（C2）。
- **v7 的可及性是准入门槛（EQ-04/EQ-05）：** 新增任何视图必须同时过 a11y 四件套与 ≥24px 目标；能力表用中文动作名，不把 24 个工具名变成新的素养税。
- **v8 的 warrant 词汇（observed / computed / declared）是 M3 的数据基础；** 我只负责不把它渲染成道德等级。
- **v1 的 `ledger` 附键不占首屏；** 我的能力清单不能把"有没有 ledger"变成新的门槛。
- **v2 的 claim-span 是"支持账"，我的时间线是"因果账的导航"；** 两者不共用一个分数（v2 T1）。

## 3. 实践方案（4 个）

**C 级自定（与 v2/v3 的标度不同，合并时必须统一）：** C0 = 修承诺（每项 ≤半天，无新持久化）；C1 = 前端/文案级（≤2 天，无新真源）；C2 = 跨包/新通道/新字段（2–5 天）；C3 = 改协议或需人类裁决（>5 天 / ADR）。

### M1 · 项目台：让项目行长出"状态 + 会话"（C1，S–M）

**最小机制：** 项目行显示 4 个派生事实——最后事件时间、artifact 数、review 数（含最新 decision）、本项目会话（按 cwd 前缀匹配，最近 3 条，可继续；会话快照是否有 `updatedAt` 未核，NOT VERIFIED）。空态从陈述句改成"下一步 + 一键复制"。
**架构（v5 T1）：** 会话归属应由 v5 的单一 resolver 提供；在它落地前，前缀匹配只作 UI 提示（标"疑似"），不写进任何证据字段。
**不做：** 不新建索引文件；不写 localStorage 之外的状态；不显示"研究进度 %"；不把计数当质量（v8 T2：artifact 数只随使用量上升，不是质量指标）。
**最小实验：** E4：5 名用户、两周、每周 2 次；计时"这个项目到哪了"；假设从 >2 分钟降到 <20 秒。falsifier：无差异，或用户把计数当质量（问卷）。
**风险：** cwd 前缀匹配会把非科研会话算进来；需按 preset 过滤或明示"含其他会话"。

### M2 · 日志视图：右栏四 mode 改为"日志 / 证据 / 待处理 / 文献"（C1 上界，M）

**最小机制：** 合并 `project.createdAt`、artifact `createdAt`、review `createdAt` + history、`exports/*` 文件时间，倒序；行 = 时间（绝对 + 相对）、事件、标题、一行状态、来源（本会话/其他/未知）；顶部"上次查看"（localStorage）+ "N 条新记录"；底部一行"未记录的：搜索、阅读、决定不记录"。复核历史折进证据卡；不再有独立 reviewer tab。待处理 = 派生清单（缺复核、被 revise、literature 缺失、review 面自述、载荷不可读）。
**架构（v5 T4）：** 派生视图必须四态（loading / empty / error / partial），禁止 `catch → []`；读失败要显示"读不到 N 个文件（原因）"，不能显示成"没有记录"。
**可及性（v7 EQ-04）：** 四个 mode 用 `role=tablist/tab` + `aria-selected` + `aria-live`；文字 ≥12px，命中区 ≥24px。
**不做：** 不新增文件、不轮询、不推断语义（accept/revise 可读，其他只显示"记录"）；不把"重复记录同字节"伪造成新事件；不把"未记录"渲染成待办（v6 后台权）。
**最小实验：** E2 + 内部正确性（同秒、去重、坏 JSON、跨项目）；假设"what changed" <30 秒。falsifier：用户把时间线当完整历史（用"导出里有没有它"题测），或同秒排序错误率 >0。
**删减：** 日志替换"证据链" tab，不新增第五个；证据仍在"产物"里，七面在卡片里展开。

### M3 · 证据卡三层：把 `/7` 换成"记录 / 可核对 / 已判定"（C1，S）

**最小机制：** 七 chip（code/execution/messages/literature = `declared`；environment = `declared` 或 `defaulted`——默认值只由缺省四键 `{platform,arch,node,python}` 判定，标"疑似缺省"；reproducibility = `computed`；review = `derived` 或 `declared`，看 `reviewSource`）。以 v8 的 warrant 词（observed/computed/declared）为基，另加 `defaulted` / `derived` 两个状态——因为 UI 必须能区分"缺省填充"与"读时派生"。**"可核对"行消费 `payloadVerified` 与 `review.signatureValid`，这是界面上唯一接近 `observed` 的证据（读时重算）；没有它时明说"本机未重算"。** `reason` 原文放 title/展开；单独一行"载荷：已核对 / 缺失 / 内容已变（记录 X 字节，磁盘 Y 字节）"；review 行拆"结论（记录者自述）/ 身份（本机未启用校验）/ 签名（仅防误改）"；checksum 全值 + 复制。
**不做：** 不做总分、不做绿勾/红叉、不把 auth 缺失藏起来、不把 declared 渲染成"不可信"、不写"已复核"（v6 P2：只能写"自述复核"）。
**限度（v6 D-03）：** M3 只修屏幕；`.science` 档案仍不带告诫，陌生读者看到的仍是 `accept / valid`。要修档案自述，得加导出字段（C2，归 v6 M-04），不归 HCI。
**最小实验：** E3；falsifier：过度信任率降幅 <15pp，或读卡时间增加 >50%。
**风险：** 窄右栏 7 chip 拥挤 → 两行/折叠；文案必须中性（"由调用方写下"而非"未验证"）。

### M4 · 动作面板 + 能力清单：把"下一步"变成可发现的（C1，M；直连 C2，L）

**最小机制：** 一个"下一步"控件，列 8 个自然语言动作（记录结果/找文献/看 notebook/计划重放/发起复核/核对/导出/导入）；每个展开显示将复制的提示词 + 会调用的工具名；旁边一张由工具注册表生成的静态能力表（24→6 组）+ 10 个 skill 名。动作只复制，不执行，按钮必须写"复制指令"。
**不做：** 不假装能直接建项目；不在 UI 里硬编码工具清单（构建期生成，防漂移）；不做 24 个按钮。
**最小实验：** E6：16 名新手 A/B，任务"记录一条结果并送复核"；测完成时间、外部文档次数、错动作率；falsifier：无改善或错动作 >20%。
**架构：** 若宿主提供受控 UI→工具通道，C2（allowlist + 逐次确认 + 与工具同权限）；否则不做。**"复制"必须诚实标注**，否则就是 P1/P5 的反例。

## 4. 路线与不做

**C0（先修承诺，每项 ≤半天）：** 把"最近会话"从静态标题改成真列表或删掉；litdb 卡"1,560 条"改成两态（读到索引 / 未检测到）；`Phase 2` 徽章改成"读取于 HH:MM"；空项目名禁止复制；成功/失败提示分色；a11y 四件套（`role=tablist/tab`、`aria-selected`、`aria-live`、命中区 ≥24px）——这是所有新视图的前置，与 v7 EQ-04 共担。
**C1（本轮，按依赖排序）：** M3 → M1 → M2 → M4。先让诚实可见（M3），再给方向（M1/M2），最后给入口（M4）。
**C2：** sidecar `sessionId`（来源会话）、`supersedes`（替代链）、`project.intent`（材料入口的 brief）、UI 直连工具（M4）。加键须守 v5 T5：layout 版本 + 双读窗口，旧归档不得被误读。
**C3：** append-only journal、多模态锚点（音频时间戳/白板区域/手写笔迹）、claim ledger（若做，归 v2 P2）、review 身份（归 v1 P3 / v8）。
**不做：** 多模态采集器（先证明锚点值得做）、仪表盘指标（研究时长/记录数）、AI 自动写日志、把聊天记录当证据、第二套索引、24 个按钮。

## 5. 自攻（这份文档最容易被反驳的地方）

1. **实验都是设计，没有跑；屏幕也没看过。** 所有"用户会看到什么"都是源码推断（`INFERRED`/`NOT VERIFIED`），未开 GUI；样本是"社科研究生"，不能外推到计算科学/医学；效应量未知，可能小到无意义。
2. **派生时间线可能制造更高级的虚假历史。** 标"未记录"是否足够，需要用户测试；同秒排序、去重、"刚记录却不在时间线"都是真实失败面。
3. **"更多视图"与认知负荷批评直接冲突。** 我用"加一个删一个"的视图预算约束自己，但仍可能不够；v3 有理由说时间线本身是打断。
4. **可发现性可能把产品推向"按钮更多"的工具箱**，背离"对话是通道"的初心。M4 的答案是不执行、只复制，但"复制"也可能变成新的形式主义。
5. **我假设用户想要方向感。** 有些研究者就是要自由漫游，任何结构化都可能是干扰；所以日志必须可关闭、可切回纯列表。
6. **成本估计来自 W03 同类改动，未实测。** 1–2 天的估计可能低估了跨 bundle 的联调。

## 6. 给 lead 的裁决点

1. 右栏四个 mode 是否允许改成"日志/证据/待处理/文献"（M2 的前提；会动 IA，需要产品维度同意）。
2. `sessionId` 与 `supersedes` 是否进 sidecar（C2；架构维度可能说"又一个字段"，但不加就无法回答"哪次会话/哪版替代"）。
3. 是否接受"先跑 v2 EPI-05，再决定证据 UI"的顺序（我建议接受；否则 M3 可能洗白）。
4. 视图预算：若 v3 的深读窗口/恢复卡与我的日志都要进右栏，谁让位？（我的建议：日志替换证据链，深读窗口进会话，不占右栏。）
5. C 级标度在五份愿景里不一致（v2/v3 与我各一套），合并时必须统一，否则"C1"会被读成三种成本。
6. v5 的跨 bundle 契约测试（P2）是否先于 M1 的会话归属上线？（我建议先；否则 M1 又多一个 resolver。）
7. v6 要求"已复核"只在他审 + 验证时使用：本机默认 off，是否接受界面长期只显示"自述复核"？（我建议接受；这是诚实，不是悲观。）
